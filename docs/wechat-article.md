# DeepSeek Harness 与桌面端：从智能体框架到跨平台应用

大模型正在从对话工具转向能够执行任务的智能体。

两者的差别不只在模型能力。一个能够真正参与开发工作的智能体，还需要理解工作区、读取和修改文件、调用工具、运行命令、保存会话，并在涉及风险操作时请求用户确认。

DeepSeek Harness 解决的正是这一层问题。

在此基础上，我们开发了 DeepSeek Harness Desktop，将官方 Harness 运行时、Web UI 和桌面进程管理整合到一个跨平台应用中，让用户可以通过常规桌面软件的方式安装和使用 DeepSeek Harness。

## 什么是 DeepSeek Harness

DeepSeek Harness，简称 DSH，是 DeepSeek 开源的智能体框架。

模型提供推理和生成能力，Harness 则负责组织模型运行所需要的环境。它连接模型、工具、文件系统、命令执行、会话记录、权限策略和用户界面，使模型能够在持续的任务上下文中工作。

通过官方 Web UI，用户可以选择本地项目作为工作区，然后向智能体提交任务。智能体能够读取和编辑工作区文件、运行命令、维护执行计划，也可以将工作委派给子智能体。涉及权限的操作，会根据当前策略向用户发起确认。

这意味着 DeepSeek Harness 不只是一个模型聊天界面。它提供的是一套完整的智能体运行环境。

## “一切皆插件”的架构

DeepSeek Harness 最具代表性的设计是“一切皆插件”。

它建立在 Cordis 之上。模型适配器、工具注册表、会话日志、智能体循环、权限策略和 Web UI 等组件，都以插件的形式进入同一棵运行树。

这种设计带来两个结果。

第一，系统中的能力可以组合和替换。开发者可以通过配置加载不同的模型、工具或业务能力，而不必修改 Harness 的主体代码。

第二，扩展能力可以保持独立。一个新的工具或服务可以作为插件接入，并与官方组件共同运行。插件卸载后，它注册的服务、事件和副作用也会随之释放。

DSH 还通过 Profile 和 Bundle 组织不同的运行形态。官方提供 Web 和 Headless 等配置。Web Profile 负责完整的浏览器应用，Headless Profile 则适合不启动服务器的一次性任务。

这种结构使 DeepSeek Harness 更接近一个智能体平台，而不是功能固定的单一应用。

## 会话、工具与权限

智能体执行一项任务，通常需要多次模型请求和工具调用。DeepSeek Harness 将这段过程组织为 Turn 和 Step。

一次 Step 包含一轮模型请求及其触发的工具调用。一次 Turn 可以由多个 Step 组成，直到当前任务不再需要继续执行。

用户消息、模型回复、工具调用和工具结果会进入会话事件日志。会话因此不只是页面上的聊天记录，也是智能体执行过程的持久化记录。重新打开会话后，系统可以据此恢复上下文。

工具执行则经过统一的受控管线。文件操作、命令执行等能力会受到工作区范围和权限策略约束。需要审批的操作会在执行前交给用户确认。

这套机制让智能体具备持续工作的能力，也让执行过程能够被观察和管理。

## DeepSeek Harness Desktop

官方 DSH 已经提供 Web UI。标准启动方式是在安装 Node.js 后执行：

```bash
npx @deepseek-ai/dsh web
```

命令会在本机启动服务，再由用户通过浏览器访问。

这种方式适合开发环境，但仍然要求用户准备 Node.js、使用终端并管理后台进程。DeepSeek Harness Desktop 的目标，是将这些运行环节收进桌面应用。

当前桌面端基于 Tauri 2 构建。安装包内置 Node.js 22.23.2 和固定版本的官方 `@deepseek-ai/dsh@0.1.0-rc.6`。用户启动应用后，桌面端会自动运行 DSH，并在服务准备完成后加载官方 Web UI。

这里需要说明项目边界：DeepSeek Harness Desktop 是独立开发的开源桌面项目，不是 DeepSeek 官方桌面客户端。

项目不包含、不复制、不修改，也不重新编译 `deepseek-ai/deepseek-harness` 源码。智能体、会话、工具和 Web UI 均由官方 DSH npm 发布物提供。桌面端负责的是运行时交付、进程生命周期、窗口管理和后续操作系统能力。

## 桌面端的运行方式

启动应用后，Tauri 会选择一个本地随机端口并启动 DSH。服务仅绑定 `127.0.0.1`，不会直接向局域网暴露。

桌面端会持续检查本地服务状态。只有官方 Web UI 完成加载后，主窗口才会显示。这样可以避免用户在启动过程中看到尚未准备完成的页面。

如果 DSH 意外退出，窗口会返回内置恢复页。恢复页会显示最近的诊断日志，并提供重新启动入口。

应用退出时，桌面端会先通知 DSH 进程组正常结束，等待插件树释放资源，再处理仍未退出的进程。运行时还会监测桌面父进程，避免桌面应用异常结束后遗留孤立的 Node.js 或 DSH 进程。

应用同时启用了单实例控制。用户再次启动时，系统会唤醒已有窗口，而不是重复运行一套 DSH 服务。

## 版本固定与运行时内置

桌面端没有在用户机器上动态安装最新版本的 DSH，而是为每个桌面版本锁定一个精确版本。

当前 v0.1.4 对应官方 `@deepseek-ai/dsh@0.1.0-rc.6`。

固定版本可以保证同一桌面版本在不同机器上运行相同的 DSH，避免 `latest` 更新后出现行为差异。升级 DSH 时，桌面端会重新验证 Web UI 启动、插件加载、会话恢复、崩溃重启和进程退出等流程。

发行构建会下载并校验 Node.js 运行时，再将 Node.js 和 DSH 一同放入安装包。安装完成后，应用运行不依赖系统中已有的 Node.js，也不需要通过 `npx` 临时下载 DSH。

## 数据与权限边界

DeepSeek Harness Desktop 使用独立的应用数据目录保存 DSH 配置、会话和运行数据，不会将这些内容写入用户的项目仓库。

默认工作区是应用数据目录中的空目录。用户需要在官方 Web UI 中选择实际项目，之后智能体才会在对应工作区内执行任务。

开发版和发行版使用不同的数据目录，便于开发调试，也避免测试数据与正式数据相互影响。

桌面窗口不会向官方 Web 页面开放通用的 Tauri Shell 或文件系统权限。后续如果需要通知、Keychain、更新等原生能力，会通过名称明确、参数受限的接口提供，而不是让页面直接获得整个系统的访问能力。

## 支持的平台

DeepSeek Harness Desktop v0.1.4 已提供以下安装包：

- macOS Apple Silicon；
- macOS Intel；
- Windows x64；
- Linux x64。

安装应用后，用户可以在“设置 → 模型”中配置 DeepSeek API Key，也可以使用 DSH 支持的其他模型服务和自定义 OpenAI 兼容接口。随后选择本地工作区，新建会话即可开始使用。

当前 DeepSeek Harness 和 DeepSeek Harness Desktop 都处在预览阶段。官方 Harness 仍在快速迭代，后续可能出现不兼容变更。

桌面端的 macOS 和 Windows 安装包目前没有商业代码签名。首次安装时，系统可能显示未知开发者或安全确认提示。

## 从运行框架到桌面应用

DeepSeek Harness 提供了智能体运行所需的模型、工具、会话、权限和插件体系。它决定智能体如何理解任务、调用能力并保存执行过程。

DeepSeek Harness Desktop 则负责把这套运行环境交付到用户桌面。它不改变官方 Harness 的能力，而是处理安装、启动、窗口、数据目录和进程生命周期，让 DSH 可以作为一个完整的桌面应用运行。

两个项目之间的关系可以概括为：官方 DSH 提供智能体系统，我们的桌面端提供跨平台运行容器。
